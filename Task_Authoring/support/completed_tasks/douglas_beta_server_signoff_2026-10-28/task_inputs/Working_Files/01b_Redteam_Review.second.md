# Red-team review (second, independent) — dg-beta-server-signoff · difficulty and call volume

Scope: `01_Scenario_Design.md` (§2, §5, §9), `01_Hardness_Manifest.draft.json`, `support/task_work/dg_beta_server/{planned_text,minted_ids,cohort}.json`,
the tool catalog, the base exports, and the tool outputs recorded in the two completed-task trajectories (`support/completed_tasks/*/07_Baseline_Trajectories`)
and calibration run logs (`support/examples/calibration/hardness/*`). Where a claim rests on unverified tool behaviour it is marked **[U]**.

## Summary

- **Call budget.** The 136-call "necessary" floor is over-counted by about 10–13 calls. A lean correct Opus run comes to **about 123–128 calls**, which is below the 130 hard minimum.
  - The over-count comes from these rows: Confluence (1, a decoy only), the client card (1, a decoy), the separate Trello comment read (`trello_get_card` with `actions:"all"` already returns `commentCard` actions; verified in the card-spend runs), Slack 3 → 1, Linear statuses (1; `linear_update_issue.state` is a string), the GitHub list (1; PR numbers come from the Linear comments), #49 and #52 (2; their tickets are excluded by the email), and sheet create + values + move 3 → 1 (`gdrive_create_file` takes `parentId` + `driveMimeType` + `content`; the handover runs used it).
- **Typical run.** I expect a typical run to land at **about 145–180 calls**. The extra comes from:
  - one wrong-tool round trip per PR (finding 1), which alone adds about 15;
  - exploration and decoy opens;
  - list output that spills to a file;
  - read-backs;
  - subagent duplication.
- **The 130–150 window.** Lean runs fall below it and typical runs often go above it. With this design, a ±7% window cannot be held per run.
- **Biggest volume/feasibility defect.** The design budgets `github_get_pull_request_comments` for the `prod:`/`rollback:` notes. In this environment that tool returns **review (inline, `#rc_N`) comments**. PR conversation comments (`#c_N`, which is where the seeds go) come back only from `github_get_issue_comments(issue_number)`. Verified in calibration run A/run3, lines 20–23: `get_pull_request_comments` → `#37#rc_1`, `get_issue_comments` → `#37#c_1`. This is both a call multiplier and a possible bimodal gate on all 9 "Y" rows.
- **Shortcut leaks.** No single record lists the 16 tickets or the on-prod answers. The conditional leaks are:
  - **Blocker [U].** `linear_list_issues(query=…)` may match comment text. If it does, `query:"match3d-backend"` or `"backend"` on team ZOM returns the server tickets in one call and the 77-read spine collapses to about 5 calls.
  - **Major.** The deploy log's Console & imports tab names ZOM-510/ZOM-256 with target. That settles both import rows without Linear and kills T15.
  - **Minor.** GitHub `rollback in:comments` returns #47/#54 directly. Slack S_DG_ASK47 maps #48 to "infinite HP boss" (ZOM-487).
  - **Cut and freeze.** Both are single reads that the card and the doc point to (by design). They are retrieval, not leaks.
- **Pass-rate prediction.** Most traps are retrieval-only and are explicitly resolved by H1/H2 text. Opus executes explicit rules in a named doc reliably (Hardness_Mastery §0 "physics"). Mechanisms likely to bite:
  - the 77-comment completeness spine (A2/A20);
  - the Douglas Sep 30 "updated prod" DM against the ZOM-503 row;
  - the freeze date (ZOM-487 only);
  - the card comment and the Gmail amendment (each about 15–25%);
  - the cut boundary, weaker than claimed (finding 7).

  **Predicted per-run average: 74–84% (centre about 78%).** That is likely above the author's 75% line, comparable to the two completed Frederick tasks (78.3% / 80.8%).
- **Bimodality.** No authority gates most rows. Two *surfaces* do, though:
  - reading all 77 Linear comments gates membership of all 16 rows;
  - using the right GitHub comment tool gates the 9 Y rows.

  Both, plus the count and key list in the DM, cascade into the reply and the Todo writes. Expect a split between runs that read everything (about 85–95%) and runs that sample or mis-tool (about 45–60%).
