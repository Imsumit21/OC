## Lessons carried forward

- **Local /rubric did not predict the platform, in either direction.** The same file got local PASS 5 and platform FAIL 2; the fixed file got a local read-only FAIL 2 and then passed. Local release is c5b89f4c, the platform's 81446b85, and the local lint has no `bundled_writes`. Seven local runs were too many: sync Evals, run one local pass, then use the platform.
- **Check a local Fix List against platform reports before copying it.** Run 1 wanted 184 rows cut to 90 by sampling comments, which is what failed frederick_q4 with 48 missing outcomes; that one was caught. Run 4's exclusion-only rows were copied and cost a platform round.
- **Guard rows, as the platform ruled:**
  - One bare count on existing records ("exactly 48 existing ART tickets"), with no range and no list.
  - No "only on tickets other than ..." rows: an idle Agent passes them, so they fail Negative Criteria.
  - No guard without a real decoy: "exactly 6 people" failed as overly specific, because the prompt has no "only" and no record sets up a share decoy.
  - Never "exactly" plus named members.
- **Rubric size:** 217 rows is the largest here (next 136, median 76). 154 are per-ticket rows. The 106 comment rows have platform backing, though the rulings covered 31 and 14 rows. The 48 assignment rows were an author's choice to escape named sets; template writes can be sampled with a volume row, as frederick_q4 did. The platform did not score the count, but every row has to be typed into the builder.
- **`revised after check` rows draw the next finding.** Six local rounds in a row found a defect in the previous fix text. Only `checked` fixes lock.
- **Apply a platform Fix List word for word,** diff against the reviewed file, and change supporting text only where a new title makes it wrong. Here that was 21 rows changed, 4 deleted, 196 byte-identical. The list gives titles and weights, not full rows, so a justification still saying "Lookup" at weight 3 is yours to fix.
- **Weights the platform set:** a ticket that says "Made by Marcus" is still 3, because assigning it needs the needs-new-work check. A rule joining Gmail, Slack and Linear is 5 even when the value is literal in one reply.
- **Accepted forms go in the title,** including first names: "Julia Lawson (or Julia)". "Maker or owner" also matched the tickets' original "Made by"; "of the Halloween work" fixed it. Keep "final" on due-date rows, because 5 of 6 runs wrote a refresh date plus an Oct 15 hand-off.
- **Corrections nobody finds add no spread.** rev3 moved the deciding facts off the swept path to clear /hardness, but four records were read by 0 of 7 rev3 runs (Frederick's Oct 10 reply, Martin's hand-off, Marcus's re-records, the end card comment). Every run dated all ads Oct 15 and assigned no ticket to Julia, so those rows fail every run together. Only the mid-findability traps separated runs: the Sep 29 mail (5 of 7) and Robert's rejection (2 of 7). Plan at least two traps at that level. Trimming rows does not fix it: a simulated 96-row set still gave SD 0.055.
- **What made /oe pass first time:** `oe_gen/model.py` re-derives every call, date and maker from the rows and asserts against `solver/truth.json`; `build_events.py` quote-checks every Expected span; a blind reviewer re-derived all 62 surfaces before /oe.
- **Read-only /rubric:** `hg_rubric_ledger.py plan` writes files; `search` and `get` reject `--no-cache`, so use `--no-index`; subagents can be refused report writes, so the report comes back as text; the harness still spills large tool output under `~/.claude`.
- **Shell:** zsh does not split `$PY` when it holds a path and a flag, and the failed command's `>` still emptied its target. Keep multi-step pipelines in a bash script (`rubric_gen/run_pipeline.sh`).
