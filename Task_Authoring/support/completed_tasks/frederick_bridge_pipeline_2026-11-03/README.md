## Lessons carried forward
- /rubric (3 rounds): a count bundled with an identity, a folder bundled with a file type, and one order row across two services are all non_atomic. Put every accepted name form (anonymized tokens too) in the title. A row joining records across services weighs 5. Every count-only population needs a named member row. Write one Process order row per write action, and make its Accept line list the same write kinds as its title. Copying the reviewer's Fix List word for word gave PASS 5.
- A record the platform asks you to cite can fail the local freeze check (the Dentsu calendar entry was created 2 minutes after freeze_utc). Name it in the evidence text and use a pre-bound record of the same fact as the V3 source. A Trello record that exists only in the SQL fails the gate's reachability lookup (base data only); cite the base card or board instead.
- The builder copy drifted from 09_Rubrics.json: R14 and R15 were typed at weight 1, which alone moves the SD from 0.106 (PASS) to 0.098 (FAIL). The title editor also escapes brackets, so `difficulty_stats.py --build` needs a binding copy (`run_forensics/rev12/platform/09_Rubrics.verifier_titles.json`). Diff the builder export field by field before the verifier runs.
