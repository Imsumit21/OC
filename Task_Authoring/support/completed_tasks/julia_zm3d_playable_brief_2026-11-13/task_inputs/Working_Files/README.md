The existing assignment in `../00_Assigments.md` and its generated
`00_Task_Context.json` are retained. This folder is prepared for authoring; it does
not yet contain a scenario, completed injection, prompt, Oracle Events, rubric,

## Select this task explicitly

Run from `/Users/sumitkumar/Source/Outlier/OC`:

```sh
export TASK_AUTHORING_TASK_DIR="/Users/sumitkumar/Source/Outlier/OC/Task_Authoring/task_inputs"
python3 -B Task_Authoring/tools/task_context.py --task-dir "$TASK_AUTHORING_TASK_DIR" --require-source
```

Give this same folder to every command; do not rely on a tool's fallback. The
generic name `task_inputs` can produce the advisory `task.folder` warning. It is
kept here as requested, not renamed or shared with another concurrent task.
Keep `task_inputs-uselater/` separate and unchanged.

The assignment and context remain the authority for persona, role, competency,
task skill, horizon, difficulty mode, selected universe and clock. Do not infer a
new date or replace an assigned value. If the assignment changes, regenerate the
context through `task_context.py --write --require-source`, not by editing JSON.

## Default flow

1. Optionally run `/create-goal` for this task folder and use its goal in a fresh
   session. Complete the pre-scenario preparation, including the fit census.
2. `/create-scenario`: design, gradable surface, draft manifest, difficulty budget,
   path-exposure and coherence work; then `/create-injection`: SQL, final manifest,
   dossier, solver and preflight. Run the required stage gates and portal reviews.
3. Go straight to `/create-prompt-writing`, draft/human writing, then check. Run
   `/create-humantime` after the prompt.
4. Save the platform's Opus 5.5 pre-check export, then use `/create-hardening`
   MODE B for the bound run forensics and budget outcome. Follow the revision
   route when needed; the user handles the portal `/hardness` review.
5. Run the six platform Opus 5.5 baselines. Prepare/draft/check Oracle Events and
   rubrics using their skills; retain the raw trajectories and verifier export.
6. Complete `/create-allfail`, `/create-difficulty` and the release gate with
   current evidence. Do not treat this scaffold as a passed task.

`/create-error-async` and `/create-reference-files` are **skipped by default**;
run them only when the owner asks. Their existing template files do not mean
friction or attachments have been configured.

For a completed stage, run its gate with the explicit task folder:

```sh
python3 -B Task_Authoring/tools/stage_gate.py <stage> "$TASK_AUTHORING_TASK_DIR" --paste
```

Only the tool may write a PASS block after a full pass. Follow
`Task_Authoring/Guide/00_Start_Here.md`,
`Task_Authoring/Guide/How_To_Author_A_Task.md` and
`Task_Authoring/Guide/Readiness_And_Evidence.md` for dependencies, attestations and
portal proof.
