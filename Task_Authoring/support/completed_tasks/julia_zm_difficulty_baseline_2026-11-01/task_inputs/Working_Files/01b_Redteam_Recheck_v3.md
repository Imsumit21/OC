# Red-team re-check — Scenario Design v3 (jl-zm-difficulty-baseline)

## Summary

v3 fixed most of the issues from the first two rounds. The two that were still open in those rounds (Slack wording and invented paths) are now resolved. Every path cited in a note exists in today's match3d tree. Every PR-linked note matches its PR's CodeRabbit file table and merge time. The demotion row now matches the code. At the clock commit (`85d1a406`, 2025-09-20, the last commit to main before the freeze), `WinRateRule.cs` has 80% promotion, ≤ 50% demotion over 10 games, and a 4-loss demotion, and `TierManager.ApplyTierChange` resets the record.

The re-check found new problems by reading the match3d git history (from the packed objects, read-only; git was not run). An agent can reach the same history with `github_get_file_contents` (with `ref`), `github_get_file_history`, `github_get_commit_files` and `github_search_code`:

- The code players have at the clock contradicts the **DDA_RETRY_DROP** story behind ZOM-303 and the "no level drop" rules row.
- The tier-code notes for all **five off-topic path members** are contradicted by the file history. One of them cites a file that was created after the clock.
- The **per-monster Live values** and the **History** tab disagree with the monster prefabs.
- The **starting-tier** row has two answers.
- **ZOM-282 → Replaced** still has a strong Live reading under rule 4's own wording.
