Fix the defects the round-1 independent verifiers confirmed (code_g1, code_h1, code_misc, redteam_grading,

## Shared interfaces (defined now, consumed across ownership)

1. `trajectory_ledger.table()` (owner SA1) adds `meta["key_events"] = {key: event}`: the last write event that
   contributed to that key's final row (CSV: the selected candidate's event; native Sheet: the last values-update or
   append event touching the key's row). Existing keys of the return value keep their meaning. The unreadable-CSV
   candidate gains `file_id` (the result id when present) and keeps `name`.
2. `surface_grader.decode()` (SA1) returns the same keys plus `table_identity` (the selected register's file id or
   spreadsheet id) and `tracker_state` ("known" | "unknown") describing the effective tracker content. `grade()`
   keeps `{slot: True|False|None}`; `decided_by()` keeps its signature (SA2 calls it).
3. `node_verdicts` report (SA2) adds, without changing existing keys: per rule `unknown_decisions` (int, number of
   decided keys whose decider model is unknown); per channel `observed`, `held`, `unobserved` (ints) and, for a
   slots-only channel, `deciding_event`/`deciding_models` taken from the failed slots' `decided_by`; `go_rule` keeps
   its shape (`independent_channels`, `channels`, `not_counted`, `run_valid`, `rule`).
4. `hardness_ledger.priors` (SA2) keeps its return shape; observations now contribute `counts.runs` trials, not
   `landed+not_landed`. `references/mechanism_priors.json` is regenerated by build after SA2 lands.
5. `hardness_forecast` (SA3): `channel_rate`'s record tuple gains `revision` and keys runs on `(revision, run)`;
   `--mechanisms` refuses an element in `engine.channel_ops` (both `forecast` and `exhaustive`) and
   `difficulty_mutation geometry --mechanisms` does the same; `_missed_batches` samples the exact conditional
   distribution (no rejection fallback) or documents the approximation as a disclosed bound.
6. `oracle_kit.check_golden` (SA3): every routed base id is read and must resolve; a routed read error, a non-zero
   `hg.py` exit, or an incomplete scan FAILs the blocking check (UNKNOWN is not available: `contract()` has only
   PASS/FAIL). Unrouted evidence stays `unverified`.

## Fix list and ownership

SA1 — grader (`tools/surface_grader.py`, `tools/gradable_surface.py`, `tools/trajectory_ledger.py`,
`support/fixtures/surface_formats/build_fixtures.py`):
G1-1 declared `gradable:false` slots join the gate matrix and the per-run score bounds as unknown cells (coverage
stays metadata); `from_revision14` preserves `gradable:false`; planted case whose full-pass bounds disagree.
G1-2 tracker content is replayed: full description replaces, append/prepend modify in order, `replace /description`
with a string value replaces; an unreadable content update makes the effective content unknown unless a later full
replacement re-establishes it; `tracker_preserves` is in the UNGRADED guard. (Design disagreement noted: an append is
readable; only the lost replacement is unknown — propagate uncertainty only to slots that can depend on the unread
part.)
G1-3 register uncertainty is decided from the delivered register's own writes (identity: the decoded table's file id),
not from "any readable rows exist"; the error candidate records `file_id`.
G1-4 `tracker_text` uses the effective description (fixes 2 and 4 together).
G1-5 `_row_keys` uses a key-list grammar (keys separated only by separators/and/or; nothing after the last key but
closing punctuation); a prose bullet counts its first key. The audit lists the 9 lines that change classification, all
outside count/entry sections; the planted `_g1_bullet_key_list` result (4) must still hold.
G1-6 `_entry_match` resolves the expected pattern against known hashes excluding the pattern itself: >1 incomparable
extension = ambiguous = False; one extension = the target; then rivals exclude the target and the pattern.
G1-7 `tracker_updates` matches the issue exactly (whitespace only) and does not fall back to unrelated updates.
G1-8 `tracker_entry` binds the value patterns to the tail after the entry's own key occurrence.
G1-9 `_range_only` drops a line only when every key occurrence is an endpoint occurrence (Counter equality).
G1-10 `email_reply` binds `message_id` and `reply_all` to the call's parameters; `slack_thread` binds `thread_ts` in
the aliased tools. No plain-body "false" search.
G1-11 the register id comes from the decoded table; `link` and `register_parent` use it and require the share call to
name it.

SA2 — attribution and priors (`tools/node_verdicts.py`, `tools/hardness_ledger.py`):
H1-1 `seeded_landings` reads supersession-resolved current records, keys `(revision, run, node)`, and a superseding
non-LANDED record removes the landing.
H1-2 priors: observations contribute `counts.runs` trials; same-(task, revision, family) observations collapse to one
trial set with `landed = max(landed)` and `not_landed = runs - landed`; a merge without declared run ids (none declare
them today) uses that conservative OR; `counts.confounded` is neither landing nor trial. A17 must stay
Beta(2.5705, 2.8544); A15 changes from Beta(1.9825, 3.4538) to about Beta(2.14, 3.17).
H1-3 `--seed-ledger` without `--reference` is an error; `rho` must be finite and in [0, 1] (validated in `priors` and
at the CLI).
H1-4 unknown deciding models are carried (`unknown_decisions`) and `own()` requires zero.
H1-5 `decider` bounds briefs by the key's own last write (`meta["key_events"]`), falling back to `max(table_events)`.
H1-6 control/channel `own` is computed from truth vs degrade across the declared columns, and every own field must be
present in the written row; a missing own field is unobserved, not held/failed.
H1-7 channel accounting separates observed / failed / held / unobserved; unobserved members never enter the held
denominator; a wholly unobserved channel proposes nothing; slots-only channels get a deciding event/model from the
failed slots; held members get provenance.
H1-8 the go rule subtracts control-explained (key, field) evidence from a channel's evidence before counting it.
H1-9 class attribution is conditional: a class difference is attributed to rule r only when `abl[r][k]` reproduces the
written class AND leaves every other written column of k equal to the written row; else cascade. (This keeps SP-039
pending, which the naive version would wrongly land.)

SA3 — forecast, oracle, labels (`tools/hardness_forecast.py`, `tools/difficulty_mutation.py`, `tools/oracle_kit.py`,
`tools/difficulty_stats.py`):
F1-1 channel-rate runs keyed on `(revision, run)`; the control-trial multiplicity documented (one trial per (run,

F1-2 `--mechanisms` refuses channel ops (forecast, exhaustive, geometry).
M6-1 exact conditional batch sampler or a disclosed bound.
M2-1 surface `U.bound_verdict` in the gate detail; a missing dispositions path is `{}`, not a traceback (low).
M5-1 golden: per-id routed accounting; read errors/non-zero exit/incomplete FAIL.
V1-1 `message_models` collects an explicit-but-falsey `model` label (classify as UNKNOWN); `model_id`/`classify_model`

Build — integration (`support/fixtures/season_pass_rev14/e2e_rev14.py` and the session scripts): E2E asserts exact

## Questions for the methodologist (must be answered before implementation)

Q1 H2 observation collapse: is "counts.runs trials, landed = max over the family's overlapping observation records,
not_landed = runs − landed" the right conservative reading of one trial per (task, revision, run, family) when the
aggregates declare no run ids? Alternative: exclude overlapping groups entirely.
Q2 F1 control rates: one trial per (run, member) discounted by the run count, or the cluster formula
`1 + (mean members per run − 1) * rho`? Which is consistent with H2?
Q3 F1 replay wording: variant A uses the ledger's priors, which include season_pass evidence and in-sample channel
rates. Is "ledger-prior variant with in-sample channel rates" the correct label, and are the five caveats in
claims_methodology.md sufficient for a partial (criterion-not-met) result?
Q4 M6: is the rejection-sampling fallback (probability `(1-theta)^1000`) acceptable as a disclosed approximation, or
must the sampler be exact?
