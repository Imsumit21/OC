# Oracle Events, route and solvability forensic audit

Audit date: 2026-10-28. Scope: read-only analysis of the preserved external OE reports, their local artifacts and histories, the shared execution contract, OE writing skill/playbook, and actual OE/stage validators. Only this report and `oe_scratch/` were created. No SQL, paid evaluation, Portal operation or outreach was performed.

## Main finding and evidence boundary

**The seven preserved original external OE reports contain zero FAIL verdicts: four PASS, two scored NON-FAIL 3, and one NON-FAIL/PARTIAL with no score.** All three tasks with a preserved repeat external OE review progress to PASS. No original report demonstrates a missing required route step, a final-response defect, a role mismatch, or an OE regression from PASS to FAIL. The evidence does demonstrate small source/qualifier defects, one provenance blocker, divergent clock contracts, local checks that predicted a cleaner result than Portal, and checks left behind after their inputs changed.

This matters to the overall investigation: repeated failures in other stages must not be attributed to OE writing merely because an OE file exists. Conversely, a local `STAGE GATE oe-check: PASS` is an authoring certificate for the evidence document and its bound inputs; it is not an independently scored external `/oe` PASS.

Evidence levels used below:

1. **Original external report, exact local bytes:** report verdict and its stated reviewed-input hashes are primary evidence of what the external evaluator reported. A report is not independent proof of every universe fact it asserts. Its underlying review records, source manifests and evaluator-release preimages are generally not supplied.
2. **Exact reviewed artifact:** independently computed SHA-256 equality proves which local OE bytes the report reviewed. It does not prove which skill produced them or that their current context equals the historical Portal context.
3. **Local check, handoff or retrospective claim:** useful workflow evidence, explicitly weaker than an original external report. A claim that a Portal round passed is retained as a claim if its original report is absent.
4. **Current implementation:** establishes the current checking boundary. It does not establish the exact skill/gate version used during a historical run.

The audit inventories skill-related artifacts and recorded gate commands. It does **not** infer that a named skill ran from a filename. Some reports expressly identify themselves as local create-oe-writing checks, and show gate output; an authenticated command/skill invocation trace is not available for every artifact. The source says skill check mode mirrors `/oe` and predicts its scores (`Task_Authoring/skills/create-oe-writing/SKILL.md:3`), but that description is not execution evidence.

## Recommendations only: targeted skill, test and gate improvements

1. **Resolve the clock before spending on downstream review.** Make the intake manifest carry the literal displayed date, resolved UTC cutoff, mapping authority, environment/universe revision, and original Portal environment/assignment hash. Add an explicit mismatch result when the local context and external reviewer disagree. Reusing neutral “task clock” wording may avoid a prose defect but must not hide a substantive unresolved cutoff. For Reviewer B, preserve the exact passing OE and already completed intake; do not request it again or adopt it silently.
