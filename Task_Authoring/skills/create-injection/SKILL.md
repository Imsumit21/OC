# Universe injection SQL + grounding dossier (01)

**Task folder (required).** `<task_dir>` in this skill and its playbook is the task folder given as this command's
argument, for example `/create-injection Task_Authoring/task_inputsRobert`. If no folder is given and
`TASK_AUTHORING_TASK_DIR` is unset, stop and ask which folder; never guess and never fall back to a default. Pass
the same folder as `--task-dir` to every tool. A new task has its own named folder
(`Task_Authoring/task_inputs<Label>`), not a bare `Task_Authoring/task_inputs`, so two tasks never share one.

Resolve this file through any symlink to locate `<bundle>/skills/<name>/SKILL.md`.
The bundle's parent is the workspace. Read `<bundle>/setup/GEN_EXECUTION.md` first, then follow the playbook
`Task_Authoring/playbooks/01_Universe_Injection.md` in full. Write only under
`<task_dir>/` (plus the forecast's ledger append through its tool, GEN_EXECUTION §1); never write to
`Evals/`, `claude/` or `HarmonyGames_*`, and never execute SQL.

`<task_dir>/01_Universe_Inject.sql`, `<task_dir>/Working_Files/01_Grounding_Dossier.md` and the final `<task_dir>/Working_Files/01_Hardness_Manifest.json` (every draft id kept or listed in `design_delta`; same `effective_profile`; verbatim `delegation_quote`s; `version_records` in the records' real time order; hazard acknowledgements with a verified `resolution`). Store this revision's SQL byte for byte in `Working_Files/run_forensics/<rev>/01_Universe_Inject.sql` (playbook S5e): every later intake binds runs against every stored revision.

## Checks
- **Known data issues (blocking):** read `references/known_data_issues/<universe>.md` (normal: NB-1–33, synth-cut: SC-1–73). No load-bearing fact, trap, Oracle Event or rubric row may rest on a card's "Don't grade" value; cite every card the task touches, with its disposition, in the coherence audit. Reviewers fail tasks on these cards.
- **No filler for volume** (Reaching the Tool-Call Minimum, 2026-10): padding is a failing error on its own. Never add a record, field, SQL comment, service or step only to raise the call count; volume comes from items that each need their own check, and every item must change the result.
- Fast advisory pre-check: `python3 Task_Authoring/tools/stage_check.py injection <task_dir>` runs the independent checks in parallel and prints one table. It is advisory; `stage_gate.py injection` remains authoritative and is still required.
- `python3 Task_Authoring/tools/hg.py lint --no-base` (drop `--no-base` once the universe data is installed) → the eval's `hg_injection_lint.py` on the task SQL: every FAIL fixed, every CHECK dispositioned in the Self-review as `LINT <check> L<line>: <disposition>`, INFO noted; it exits 0 even with FAIL flags, so read `counts.FAIL`; a clean lint is not a PASS. The injection stage gate re-runs it with base data and blocks on any FAIL or undispositioned CHECK. `sql_lint.py`, `base_check.py` and `hardness_gate.py` still run — different rules, all must pass.
- **Base claims (blocking):** `python3 Task_Authoring/tools/base_claims.py <task_dir>/01_Universe_Inject.sql --task-dir <task_dir>` → `BASE CLAIMS …: PASS`, pasted verbatim in the Self-review. Every release branch named in seeded text must exist (B1), be named only once it exists (B2, window start = first `#builds` build or first own commit), a pick claim must fall inside the branch's window (B3), and when git has commits naming the ticket (or the PR's commits) the claimed branch must contain them (`git branch --contains`, B4). `/prompt` §3.2 runs exactly this reading; `base_check` does not. Run it before any solver/preflight work: a B-finding changes trains and therefore the truth.

## Preflight (playbook S4b–S5e)
- Blocking: the solver declares `RULES[r].controls` (+ `over_application`), `CHANNELS` and `base_route(record_id)` (S4b); `python3 Task_Authoring/tools/oracle_kit.py check --task-dir <task_dir> [--previous-sql <revision N-1 SQL> --previous-truth <its truth.json>]` → PASS, including `contract.controls` (every declared control member is a solver key; every over-application operator and channel is live) (S4b); `python3 Task_Authoring/tools/difficulty_mutation.py mutate --task-dir <task_dir>` with a written disposition for every rule, channel degrade and intervention result in `01c_Dispositions.json` (S5b; EQUIVALENT is never auto-labelled FALSE); geometry U > 1 − cap (S5b′), and a non-composable solver's U UNVERIFIED needs a written `geometry.U` disposition.
- Advisory, UNCALIBRATED: the geometry margin L_max; `tools/trap_liveness.py` flags, each with a written disposition (S5c); optional blind probes (S5d); `python3 Task_Authoring/tools/hardness_forecast.py forecast --task-dir <task_dir> --model <baseline model> --preregister [--channel-rate <channel>=<e>]` (S5e), pre-registered in the ledger before the platform run. A declared channel takes its rate from the model's ledger records of its family; with no record, pass a disclosed `--channel-rate` or the forecast prints UNPARAMETERIZED and does not simulate it.
- Then `python3 Task_Authoring/tools/preflight_report.py --task-dir <task_dir> [--forecast <forecast.json>]` writes the report, bound by sha256 to the SQL, solver, surface, manifest and dispositions; any later edit to one of them makes it stale.

## First-pass checks (playbook S5g; hard gates 18–21)
- **Budget on this revision** (`budget.injection`): every unit's `decider` names the injected or base record; `python3 -B Task_Authoring/tools/difficulty_budget.py check --task-dir <task_dir>` → PASS.
- **Path exposure** (`exposure.units`): `python3 -B Task_Authoring/tools/path_exposure.py check --task-dir <task_dir> --write` → every anchor and coin-flip unit OFF-PATH. An EXPOSED unit is moved to another carrier, never accepted with a note.
- **Coherence sweep** (`sweep.forks`): `coherence_sweep.py candidates`, two cold reviewers from `coherence_sweep.py brief`, every fork settled in data, a closed rule and census for every open set, siblings of every defect checked, each seeded fact checked against the whole base; `python3 -B Task_Authoring/tools/coherence_sweep.py check --task-dir <task_dir>` → PASS. On revision N+1 the sweep is scoped with `revision_scope.py scope`.
- **Rubric shape** (`skeleton.present`): `python3 -B Task_Authoring/tools/rubric_skeleton.py build --task-dir <task_dir> --write`, then `check` → PASS.
- **Injection-built scenario** (fit census `NO NATURAL COHORT`): the cohort and its haystack are written as a spec and rendered with `python3 -B Task_Authoring/generators/render.py render --task-dir <task_dir>`.
- These are first-pass checks: each prints WARN while its mode in `references/first_pass_policy.json` is `warn` and blocks once the owner sets it to `block` (`python3 -B Task_Authoring/tools/first_pass_controls.py modes`). Fix what they report either way.

## Stage gate (blocking)
Run `python3 Task_Authoring/tools/stage_gate.py injection <task_dir> --paste`. Handoff is blocked until it prints `STAGE GATE <stage>: PASS`; `--paste` writes that output into the Self-review, and the next stage's gate refuses an upstream artifact without a current PASS block. It checks structure and freshness, evidence pointers, pasted tool outputs (re-run and compared), persona reach, universe-KB use and the self-review's counter-readings, plus the preflight: bound to the current files (`structure.preflight`), the solver contract (`solver.contract`, re-run with `--rerun all`, including `contract.controls`), every mutation result, channel degrade and intervention dispositioned (`mutation.dispositions`) and geometry U (`geometry.upper_bound`, re-run; U counts channel degrades and over-application operators); the geometry margin, liveness dispositions and the forecast are WARN only. Fix the artifact; never edit the gate's output.
